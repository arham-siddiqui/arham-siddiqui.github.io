Overview

I built StreetSmart through MIT Beaver Works Summer Institute as an assistive navigation perception system for visually impaired users. The project combined computer vision, environmental audio classification, and text-to-speech feedback into a Streamlit application that could take an image or audio clip, infer the relevant street sign or hazard, and turn that result into a spoken navigation cue. My goal was to move beyond a single-modality detector and build a prototype that could reason over both visual street context and acoustic hazards, because real navigation requires awareness of signs, moving vehicles, construction sounds, sirens, and spatial position at the same time.

Problem

Visually impaired navigation systems need to communicate useful information without overloading the user. A raw object label is not enough: a user needs to know what was detected, where it is relative to them, and whether it is a safety-relevant cue. I framed StreetSmart as a perception-to-language pipeline: detect salient signs or sounds, convert model outputs into compact semantic messages, and speak those messages through a low-friction interface. This required tying together model training, preprocessing, inference, localization heuristics, and user-facing feedback rather than treating each model as an isolated notebook experiment.

Vision Pipeline

For the visual branch, I worked with road-sign image data and annotation files, parsing XML annotations with `xml.etree.ElementTree`, extracting filenames and class labels, balancing the class distribution by filtering a fixed number of examples per class, and converting images into normalized arrays for training. I experimented with TensorFlow/Keras CNN classifiers using convolutional blocks, max-pooling, flattening, dense layers, dropout, one-hot encoded labels, and Adam optimization with categorical cross-entropy. I also explored EfficientNetB0 as a pretrained feature extractor, then moved toward an Ultralytics YOLO-based detector because object detection is more useful for navigation than whole-image classification: it provides bounding boxes, labels, confidence, and spatial position in the frame.

The deployed Streamlit code loads a custom YOLO model from `best.pt`, runs inference on uploaded images, and extracts the detected object summary from the YOLO result object. I added quadrant-style localization logic using bounding-box center coordinates relative to the image dimensions. If the detected object center was near the upper-left, upper-right, lower-left, lower-right, left, right, above, below, or center region, the application generated a corresponding spatial phrase such as "top right," "to the left," "above you," or "in front of you." This turned vision outputs into navigation language instead of stopping at a bounding box.

Audio Pipeline

For the audio branch, I built an environmental sound classifier around Librosa feature extraction. I extracted compact audio fingerprints from each clip using zero-crossing rate, spectral centroid, spectral bandwidth, spectral contrast, spectral rolloff, RMS energy, chroma features, and MFCCs. I organized the training labels into seven hazard categories: car horn, dog barking, drilling, engine idling, jackhammer, siren, and violence. Those classes were chosen because they represent navigation-relevant acoustic events that can signal traffic, nearby machinery, construction, emergency vehicles, or potential danger.

I trained a Keras dense neural network with alternating 512-unit and 256-unit ReLU layers, dropout regularization, and a seven-way softmax output. The application preprocesses uploaded audio by flattening, truncating, or zero-padding the waveform to the expected model shape, runs the TensorFlow model, and maps the highest-probability class to a spoken label. The notebook confusion matrix helped me evaluate which classes the model separated cleanly and where confusions remained, especially for acoustically similar urban sounds.

Application Architecture

I integrated the vision and audio branches into a Streamlit app called "StreetSmart: Sign and Sound Detection." The application uses `@st.cache_resource` to load the YOLO and TensorFlow models once, accepts image uploads through a file uploader, converts images through PIL/OpenCV/NumPy preprocessing, runs object detection, and displays the uploaded image and detection output. For audio, the app writes uploaded files to a temporary WAV path, reads them with SoundFile, applies model-specific preprocessing, and returns the predicted hazard category.

The final user-facing layer is text-to-speech. I used `pyttsx3` so detections could be spoken aloud immediately: the sign or sound class is converted into a short phrase, and the spatial localization logic adds direction when a visual object is detected. This made the capstone a complete inference loop: input stream, preprocessing, model inference, semantic post-processing, spatial phrase generation, and auditory feedback.

Results

The final repository contains trained model artifacts for both modalities, including `best.pt` for YOLO-based visual detection, `yolo_model.h5`, `audio_model.h5`, and `audio_model_v2.h5`. It also contains notebook iterations for image classification, YOLO training, audio fingerprinting, confusion-matrix evaluation, and text-to-speech integration. The most important result for me was not just training a model, but building a prototype that connected perception outputs to a spoken assistive-navigation interface.

Conclusion

StreetSmart helped me think about assistive navigation as a multimodal systems problem. I had to combine computer vision, audio signal processing, neural-network training, model serialization, Streamlit deployment, and text-to-speech feedback into one user-facing tool. The project also showed me why evaluation matters differently in assistive technology: a visually impressive detection model is only useful if its outputs become timely, interpretable, and actionable cues for the person using it.
