Overview

I built Curriculearn as an AI-powered curriculum optimization system that treats a lesson like an input program and repeatedly evaluates, diagnoses, edits, and re-scores it against simulated cognitive-response metrics. Instead of generating lesson material from scratch, I designed the system to ingest teacher-authored PDFs, PowerPoints, Word documents, plain text, or raw lesson content, segment the material, convert each segment into a semantic brain-state representation, and use those trajectories to identify cognitive overload, weak concept flow, low retention support, and low multimodal reinforcement.

Introduction

My central problem was that teachers usually do not get granular feedback on how a lesson will feel cognitively until students are already interacting with it. I built Curriculearn as a feedback loop for that gap: parse the lesson, simulate how a learner's representational state changes over time, translate those changes into interpretable pedagogy metrics, and then generate targeted revisions only where the lesson is predicted to break down.

Methods

I organized the backend pipeline as a multi-agent NeuroCompiler system. Agent 1 parses uploaded documents using PDF, PPTX, DOCX, and TXT extractors, then normalizes the output into structured lesson segments. Agent 2 uses a sentence-transformer model, `paraphrase-MiniLM-L3-v2`, to produce 384-dimensional semantic embeddings for each segment as a lightweight proxy for brain-state trajectories. Agent 3 translates those embeddings into learning metrics by computing text-complexity signals, pairwise semantic distance, cosine similarity between adjacent segments, novelty, information density, and concept reactivation.

I converted those metrics into typed Pydantic data contracts, including `StructuredLesson`, `MetricScores`, `MetricReport`, `Diagnosis`, `EditOperation`, and `OptimizationResult`. I defined the learning objective around engagement, inverse cognitive load, concept flow, reinforcement, and multimodal support, then used a deterministic diagnostician to prioritize issues such as cognitive overload, poor concept flow, low retention, novelty spikes, and low multimodal support. The curriculum editor then generates bounded edit candidates such as splitting overloaded sections, adding transitions, inserting retrieval questions, simplifying explanations, or adding examples/analogies.

What Was Built

I worked on the end-to-end product architecture: a Flask REST API for upload, analysis, optimization, and visualization; a Next.js/TypeScript frontend for classroom and document workflows; and a Three.js brain visualization that maps curriculum metrics onto interactive brain regions. The frontend calls stateless `/api/upload`, `/api/analyze`, and `/api/optimize` endpoints, stores parsed lesson content client-side, and renders learning score, engagement, cognitive load, concept flow, retention, novelty, information density, reinforcement, and multimodal support as actionable outputs.

I built the optimization loop to evaluate the original lesson, run diagnostics, generate candidate edits under bounded segment-growth constraints, re-simulate each candidate, and keep the revision only if it improves the global learning score. I also included local demos, sample lessons, deployment configuration, persistent JSON-backed result storage, optional Claude-powered diagnostician/editor variants, and frontend brain-region components for section-level metric exploration.

Results

In a committed sample optimization run on an introductory photosynthesis lesson, my system improved the learning score from 55.8 to 57.4 over two optimization iterations. In that run, the optimizer identified an overloaded segment containing chlorophyll, photons, ATP, carbon fixation, glucose, and light reactions; split it into an intuition-first segment and a core-detail segment; and preserved the revised candidate because it improved the objective score. This demonstrates the loop I wanted: detect the exact weak segment, generate a pedagogically motivated edit, and validate the edit through re-simulation rather than accepting it blindly.

Conclusion

Curriculearn became my full-stack curriculum compiler: document ingestion, semantic brain-state simulation, interpretable educational metrics, diagnosis generation, candidate rewriting, score-based optimization, and a visual interface for understanding the result. I see the technical value of my work in the coupling between language-model-style lesson editing and a separate evaluation signal, which creates a measurable loop for improving instructional materials instead of relying only on unconstrained generation.
