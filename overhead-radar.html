Overview

I built the Overhead Movement Alarm Radar (OMAR) as a head-worn assistive navigation system for blind and visually impaired users who need awareness of obstacles that a cane often cannot detect, such as tree branches, signs, shelves, and other hazards above waist level. The core idea was to move overhead perception into a hands-free wearable: ultrasonic sensors detect nearby objects in front of and above the user, while left/right haptic motors communicate the direction and proximity of the obstacle without using audio or visual feedback. I designed OMAR to preserve the user's hearing, avoid adding another hand-held device, and provide tactile spatial information directly through the head-worn form factor.

Problem

Traditional mobility tools are strong at detecting ground-plane obstacles, but they leave a sensing gap for overhead hazards. That gap matters because a blind user can collide with low-hanging branches, wall-mounted signs, open cabinets, construction barriers, or other objects that sit outside the sweep path of a cane. My design goal was to create a low-cost wearable system that could detect these hazards before contact, encode both side and distance through vibration, and remain comfortable enough for repeated use. I also wanted the device to be mechanically understandable and manufacturable, which is why the patent application emphasized modular sensor mounts, internal wiring, and a head-worn integration strategy.

System Architecture

I implemented OMAR around a central computing module, ultrasonic sensing, and haptic actuation. The wiring diagram maps two ultrasonic sensors to trigger/echo pins on the computing module and maps two vibration motors to output pins for left/right tactile feedback. Each ultrasonic sensor alternates between transmitting and receiving ultrasonic pulses, and the firmware converts the echo timing into distance estimates. When a sensor reports an obstacle within a predefined adjustable threshold, the corresponding haptic motor activates, giving the user a directional cue tied to the side of the detected obstacle.

The patent application also describes an extensible architecture: additional ultrasonic sensors and haptic motors can be added for higher directional resolution, and the feedback logic can use pulse-width modulation (PWM) so closer obstacles produce stronger vibration intensity. I treated PWM as a more informative feedback channel than a binary alarm because it lets the user infer not only that an obstacle exists, but also whether they are moving closer to it. In practice, this made the device a tactile ranging system rather than just an on/off warning system.

Mechanical Design

I helped develop the head-mounted sensor geometry so the ultrasonic modules would point toward the region where overhead hazards are likely to appear. The application figures show an adjustable mount for each ultrasonic sensor, including front, side, and top views with measured dimensions. The mount seats the sensor board, protects the wiring from stress and breakage, and angles the transducers outward from the cap so the detection cone intersects the user's forward overhead path. The application specifies ABS as a practical mount material because it is low-cost, durable, and appropriate for prototyping and repeatable manufacturing.

The wearable layout placed the computing module toward the rear of the cap to improve balance and comfort, routed wiring through the head-worn structure, mounted ultrasonic sensors toward the front left and front right, and positioned haptic motors inside the cap slightly above the user's temples. This layout made the feedback spatially intuitive: a left-side detection activates the left haptic motor, and a right-side detection activates the right haptic motor. By separating the sensing modules from the haptic actuators while keeping both embedded in the cap, I could preserve a clean exterior form factor while still maintaining serviceable electronics.

Firmware And Sensing Logic

I structured the embedded loop around sensor initialization, distance acquisition, threshold evaluation, and haptic output. On startup, the firmware initializes trigger and echo pins for each ultrasonic sensor, initializes vibration pins for each haptic motor, declares duration and distance variables, and loads the distance thresholds used for actuation. During operation, the computing module repeatedly triggers each ultrasonic sensor, reads the echo duration, converts the pulse travel time into an estimated distance, and compares that distance against the active threshold. If the measured distance is inside the hazard range, the corresponding motor turns on; if the detected object is outside the range, the motor remains off.

I designed the control logic to support adjustable distance ranges because user height, walking speed, preferred warning distance, and environment all change how early a hazard should be communicated. The patent application also outlines a PWM extension where the firmware maps distance bands to vibration duty cycle, allowing the vibration amplitude to increase as the user approaches an obstacle. This gives the system a continuous haptic gradient: weak vibration for farther hazards, stronger vibration for closer hazards, and side-specific activation for left/right localization.

Testing And Iteration

I iteratively prototyped and tested OMAR over multiple years with the same blind user, using feedback from real outdoor and indoor navigation scenarios to improve the sensing range, sensor orientation, feedback timing, mount durability, and wearable comfort. The testing process was important because ultrasonic sensing is sensitive to angle, surface geometry, and environmental context. A flat sign, a leafy branch, and a narrow pole can return very different signals, so I had to think about practical detection behavior rather than only idealized sensor readings.

I also distributed OMAR to 50+ members at the Hatlen School, which helped move the project beyond a single prototype and into a real assistive-technology deployment context. That distribution forced me to think about repeatability, usability, robustness, and how clearly the device communicates its purpose to users who may have different mobility habits and comfort preferences. The project ultimately earned the California State Seal of Civic Engagement, reflecting both the technical build and the community-facing impact of the work.

Results

OMAR became a wearable overhead-obstacle detection system with a complete sensing-to-feedback pipeline: ultrasonic transduction, echo-time distance estimation, threshold-based hazard classification, side-specific haptic actuation, adjustable sensor mounting, internal cap wiring, and an extensible PWM-based feedback model. The most important result was that the device translated an environmental hazard into a tactile cue quickly enough for a blind user to react without blocking hearing or requiring another hand-held tool.

Conclusion

OMAR taught me how to approach assistive technology as a full systems problem. The electronics had to work, but the device also had to be wearable, directional, interpretable, adjustable, durable, and respectful of how blind users already navigate. I built the project across embedded sensing, mechanical design, haptic feedback, user testing, patent documentation, and deployment, and the experience shaped how I think about engineering: the best assistive systems are not just technically clever, they are designed around the actual sensory channels, habits, and safety constraints of the people using them.
